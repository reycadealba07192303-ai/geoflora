# Hybrid recognition and progressive learning

Implementation record: November 1, 2026. The current MobileNetV2 artifact was preserved; this work added a supplementary visual-reference path and stricter ecological/training gates. No training run or model promotion was performed.

Follow-up on closed-set CNN overconfidence and user disagreement handling: [prediction safety check](closed-set-prediction-safety-2026-11-01.md). The active model remains unchanged; above-threshold CNN classes are now presented as tentative suggestions.

## Recognition and verified references

- FastAPI `/embed` exposes an L2-normalized 1,280-feature vector from the loaded MobileNetV2 backbone, tagged with the active model and embedding version. It is separate from `/predict` class probabilities.
- A sighting enters MongoDB `verified_image_references` only after contributor reference-use consent, a human-confirmed species decision, a separate reviewer reference-eligibility approval, and the image-quality check. Reference documents retain the review rationale, reviewer, consent/license basis, source observation, provenance, hashes, embedding, and model version.
- Exact-image matches and embedding similarity are kept as separate methods. Exact matches show their accepted botanical source. Different-photo matches appear only as unverified suggestions when the CNN is uncertain; the similarity value is explicitly uncalibrated and is never shown as model confidence or used to verify a report.
- Exact and perceptual-hash checks reject duplicate references. Administrators can invalidate a reference at `/api/admin/references/{reportId}`; invalidation deactivates the record and adds an audit event. Approved references are retried when an administrator opens the review queue if indexing previously failed.
- The review queue reports reference-index state separately from botanical review and training: `pending`, `indexed`, `ineligible`, `failed`, or `invalidated` (and `not_requested` when consent was not given). Failed jobs expose a safe summary in the UI; detailed diagnostics stay in server logs. Pending and failed approved records are retried from the review queue.
- Reference consent is separate from training consent. Non-target species may be reference examples without becoming invasive classes.

## Ecological scope and automatic training

- Species decisions now carry `target_invasive`, `non_target`, or `pending_ecological_review`. Botanical review alone leaves ecological status pending. Only an administrator can assign a confirmed ecological status, with a Philippine-relevant HTTPS source, rationale, and explicit confirmation.
- Default map/analytics and catalog verified-occurrence counts include only verified reports whose ecological status is `target_invasive`. The optional pending layer remains clearly separate. Existing historical verified reports without an explicit ecological status are not silently reclassified and are omitted from confirmed invasive counts until reviewed.
- Training requires a verified report, contributor training consent, confirmed target-invasive status, a human detailed identification, and a separate human training-eligibility decision. The default readiness gate is 10 distinct report/observation groups per class (`GEOFLORA_MIN_TRAINING_GROUPS_PER_CLASS`); exact/near duplicates, licensing and historical-test safeguards still apply. Candidates remain experimental until explicit administrator promotion.
- Staging folder names and source flags are not ecological decisions. Staging records cannot join invasive training unless their metadata contains an explicit confirmed status, administrator confirmation/reviewer, Philippine ecological citation, and rationale. Current `source_flagged` and `introduced_review` folders fail this gate. Non-target/look-alike staging records are excluded from invasive training.

## Tawa-tawa status and limitations

Eleven legacy sighting documents have no persisted reference-index status yet. The local corpus contains a taxonomy record but no eligible Tawa-tawa field-reference pair. Therefore same-species ranks, different-species comparisons, unknown-image false matches, and retrieval scores cannot be measured honestly yet. No recognition result is claimed for Tawa-tawa.

The admin workflow already separates reference eligibility from CNN-training eligibility. A submitted image gets an embedding only after explicit contributor reference-use permission, an authorized human species verification, a separate reviewer reference-eligibility approval, image-quality checks, and duplicate checks. Indexing state is now persisted and visible in the review UI. A successful record is stored in `verified_image_references` with its embedding version; failures are retried from the admin review queue. This does not create or imply consent or botanical verification for existing records.

To run the requested two-photo check, obtain two independently photographed Euphorbia hirta field images (different capture events, preferably different observers or locations) with original source/provenance and written rights permitting GeoFlora visual-reference use. Submit each through the existing Identify/report flow and ensure the contributor explicitly grants visual-reference permission. An authorized reviewer must inspect each image, confirm the species and provenance, and separately approve reference eligibility with a rationale. The queue should move each from `pending` to `indexed`; verify two active MongoDB records with different source observation/group IDs and compatible embedding versions. Then query each photo against the index, recording raw cosine ranks/scores for the same-species candidate, visually similar other-species candidate(s), and a genuinely unrelated/unknown plant. These scores remain uncalibrated retrieval similarities, not confidence or accuracy. Do not add a cutoff until a grouped positive/negative evaluation set exists.

Similarity thresholds have not been calibrated: there is no grouped positive/negative reference set. Until that exists, similarity is only a candidate list beneath an uncertain CNN result.
